Brand guidelines

The mark is a seal.

RiskMandate produces a record somebody puts their name to. The mark says that before a word is read: a stamp with a monogram inside it, registration ticks on the axes, and a quiet inner ring. It signals counter-signature and provenance to the audiences that matter — underwriters, risk committees, boards.

01 · The mark

One mark, three fidelities.

The containered mark is the default. The knockout drops the container for dark surfaces where a filled tile would sit heavily. Below 24px the detail genuinely dies — so there is a simplified cut rather than a blurred one.

02 · Rules

Five things not to do.

Do not recolour it

The green is #1A7F5A and the container is #161615. The mark never appears in another hue, and never in full colour on a coloured field.

Do not use the detailed cut below 24px

The registration ticks and the inner ring turn to mud. Use the simplified mark, which keeps the ring and the monogram only.

Do not stretch, rotate or add effects

No drop shadows, no gradients, no outer glow. A seal that looks printed is doing its job.

Do not redraw the monogram

RM is set in the mono face at a fixed optical size inside the ring. It is not a text layer to be re-typeset.

Do not crowd it

Leave clear space of at least half the mark's width on every side. In a UI bar that means the mark, a gap, then the wordmark.

And the honest caveat from the concept itself: seals skew traditional. Used heavily and at large sizes it can make a young company look like a compliance vendor. Keep it small, keep it quiet, and let the typography carry the personality.
03 · Colour

Ink, green, warm greys.

Every colour in the product is a token. Nothing is a literal hex outside the token block — the same rule the code follows.

04 · Typography

System faces, deliberately.

No web fonts, no CDN, no flash of unstyled text, and nothing to load before the page is readable. The system sans carries everything; the system mono carries labels, keys, numbers and anything that should read as machine output.

05 · Downloads

Take the assets.

SVG for anything that scales, PNG where a raster is required, EPS for a printer. All served from the vault.

About the EPS. Conference stands and print shops ask for .eps and reject everything else as pixelated. These are real vector, drawn from the same geometry as the SVG, with one deliberate difference: the lettering is converted to outlines rather than named as a font, because an EPS that names a font is an EPS that looks different on somebody else’s machine and we never see the proof. No background is painted, so the artwork drops onto any ground. The letterforms are Geist, which this site self-hosts under the SIL Open Font License. Written by scripts/site/render-brand-eps.py and proofed by rasterising the file that ships.

06 · Boilerplate

And the words.

Anybody who asks for the logo asks for a line about us in the same breath, so both live here. Eight lengths, saying the same thing in the same order, so choosing between them loses detail and never changes the claim. Paste the longest one the field accepts.

Long 269 words · 1491 characters · profile or about page
RiskMandate creates and sells Agent Behaviour Policies. An Agent Behaviour Policy is a working record, for one agent in one deployment, of four things: everything it can actually reach, what you authorised it to do, the gap between those two, and what stands in the way. Three of the four can be written down by the people who run the agent. The fourth, the gap, is worked out from the first two, and it is usually the one nobody has looked at. It is a portable vault rather than a document, because four audiences need different things from one record. The operator needs instructions, leadership needs a decision, security needs evidence, and an insurance conversation needs explicit scope and open questions. One record, several views, with a named owner, a review trigger and every version kept. A policy is a draft, and it is meant to be argued with. It goes to the people who built the agent, the people who own what it touches and the people accountable for it, and each corrects the part they know. It is never finished, because the agent is not finished. The question it answers is not what model somebody bought. It is what the agent can do that nobody in the business has fully understood yet. That is not a property of the model. It is a property of this deployment, so a policy is fitted to a twin of the environment the agent is actually in. That is where a generic shape stops being generic and becomes yours, and it is the only point at which the exposure means anything.
The full version. The third paragraph is what is being sold rather than a description of it, and the last is the one that matters: risk is a property of the deployment, not the model.
