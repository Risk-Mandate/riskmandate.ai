# v1.37.0 — Rules: one worry, one line

8 October 2026. The lead's memo of 7 October said the path from a stranger to a customer breaks before
anybody tries anything. The next day: *we are asking people to do stuff without a clear understanding of
what they get on the other side, and for what. The advantage of these rules is that they give people
something very specific: oh, I'm worried about that, this is going to protect that. And it's fractal;
it's about learning which one works better.* This release is that, built.

- **A new family of pages, `/rules/`: 24 rules.** Each one asks a question, *do you want your agent to
  do this?*, says the worry in the reader's words, says what you get, and gives the one line to paste
  into the agent's instructions, with a paragraph for when you want the agent to understand rather than
  obey. Two answers: *never*, and *ask me first*. The first four are the lead's own examples: other
  sessions' history, the secrets on your machine, jobs that outlive the session, and your connected
  accounts. The other twenty come from every published row where an agent holds a capability with
  nothing in the way and no way back; all ten such capabilities now have a rule.
- **Honest about what a line is.** Every rule says that a line in the instructions is a request to the
  agent, an expectation in the vocabulary every behaviour policy uses, and names the stronger barrier
  where one exists: a Claude Code deny or ask rule, the sandbox, managed settings, an organisation's
  connector setting, each quoted from the vendor's own page with the date it was read. Reading those
  pages corrected the first draft: the sandbox is off by default, reads credential files unless they
  are listed, and does not cover Claude's own Read tool. Where we have read no vendor page that offers
  more, the rule says so.
- **Before and after, for the first four.** The same request, once without the line and once with it,
  on our own deployment, as a described scenario with nothing executed; one run each. Three changed
  clearly: the agent stopped reading every recent session's transcript, waited for a yes before
  creating a routine, and asked before reading mail and again before inviting a third person. The
  secrets rule changed less, because the agent was already careful not to print a secret; it stopped
  running the script that uses the credentials. The method page says what one run can and cannot show.
- **The learning loop.** Every rule ends with *this worries me*, *it worked* and *it did not work*.
  Each opens the contact form with the rule's id and version filled in; the form encrypts in the
  browser as before, and a person reads it. The rules people say worked are the ones written next.
- **One file of rules per agent**, under `/rules/sets/`, thirteen of them: every rule for that agent
  as one block to paste once, with each rule's id and version.
- **The path.** Try it now leads with the rules, thirty seconds and one line, with the twenty-minute
  Gmail workflow as the second step; the home page's builder links to them.
- **Built, not written by hand.** `scripts/site/build-rules.mjs` reads each rule, the vocabulary and the
  vaults' grants, refuses a rule without a worry or a barrier statement and any score-shaped field, and
  its check runs in CI. `--candidates` prints the rows that still need a rule.

The second number moves because this is a new section aimed at a new reader. Not done: the lead's early
users have not test-driven a rule yet; the list is the lead's. *Ask me first* is this site's extension
of the grammar and is on the list of asks for the model site.
