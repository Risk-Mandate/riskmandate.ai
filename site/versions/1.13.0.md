## Nine template vaults and a directory, one per application

**The behaviour-policy section becomes a directory.** [abp-vaults.html](abp-vaults.html) now
reads like a connector directory: one tile per target application, a glyph, a one-line
blurb, the four counts, a live chip, and a plus to open it. Nine vaults are available —
every deployment shape the model site publishes — and four applications are listed as
*asked for, not built*, because their grant is not published yet and nothing here is
invented to fill a grid.

**Nine vaults, nine pages, one command each.** The eight new shapes — Claude Code on your
machine with confirmations on and off, Claude Desktop, Claude in the browser with
connectors, ChatGPT in the browser, a browser extension, GitHub Actions, a scheduled job —
were fetched from abp.sgit.ai, built with `build-abp-vault.mjs`, each checked row for row
against the published delta, and pushed as their own vaults with public read keys. Every
one has a page (`abp-vault-<slug>.html`) generated from one catalogue,
`site/vaults/index.json`, by `scripts/site/build-abp-pages.mjs`; the page components and
CSS live once in `scripts/site/abp/`. Adding the tenth vault is adding a row.

**The vault app, for someone who does not know what an ABP is.** A *What is this?* view:
the problem in a paragraph, the four words with the verb attached to each, why there is
no score, what it is not, and what to do with the vault depending on who you are. The
hero links to it. The *no score* badge is gone; the card now opens its explanation with
the question a new reader actually has — *looking for a score? there is none, on purpose*.

**Smaller fixes.** The host HUD is minimal, so the vault's own navigation is the
navigation. The do/don't rows are a fixed two-line grid, so capability, enforcement tag
and description line up on every row.

**Vaults in vaults: the application vault is data.** The renderer moved out of every
application vault into one app vault (`fl3i7lu4`, public read key), versioned once. Each
application vault now carries a hundred-line loader as its `index.html` — the same bytes in
all nine — which fetches the renderer over a sub-vault link when the host resolves one,
directly from the app vault with its public key otherwise, or from a static copy beside the
vault, and boots it against the vault's own files, naming the route it took in the top bar.
The generator writes the loader and `data/app.json` instead of a copy of the app; a buyer's
private vault works the same way with no code copied into it. The design, the routes and
the two open asks to the platform (the link file's `ref_id`, and whether sgit can write the
owner record) are in `docs/briefs/architecture__vaults-in-vaults-for-behaviour-policies.md`.

Vault `ruj286tr` is at its fifth commit, the eight new vaults at their second, the app
vault at its second.
