# v1.38.5 — Review feedback: every action, a debug column, and a key per browser

9 October 2026. The lead asked for the review page to become a proper feedback loop: see the page the way the
reader saw it, see every message and its status, and be able to answer one reader in a way nobody else can
read. This release does that on the private review page, `home-diff.html`, and changes nothing else.

- **Every action is an event.** Besides what the page already recorded, it now records where the reader stops
  scrolling and which way they moved, how long they stay on each section, the links they follow, the boxes
  they focus, what they copy, the slider grabbed and released, window resizes, the tab hidden and shown, and
  script errors. It sends every thirty seconds while there is something new, as well as on the buttons and
  on leaving a comment box.
- **A key pair of its own for each browser.** On first open the browser makes a signing key (ECDSA P-256) and
  a reply key (RSA-OAEP 4096), as sgit's own identities do, and keeps them in the browser with the private
  halves not extractable. The browser's id is its signing key's fingerprint; no name or email is in it. Every
  send is signed, and the signature covers the record itself, not only the ciphertext.
- **The reader checks and pins.** `scripts/review/read-feedback.mjs` verifies each signature and that the id
  belongs to the key, and pins each browser's keys in the review vault on first sight.
- **Replies that only one browser can read.** `scripts/review/reply.mjs` encrypts a note to a browser's pinned
  reply key and publishes it in `site/assets/review/replies/`. The page decrypts it on open and shows it at the
  top. The file is public; another browser cannot open it, which was tested.
- **A debug column on the right** (the Debug button, or `?debug=1`): this browser's keys, the lane and its key
  check, every send with its reason, size, time, HTTP status and the server's answer, the replies, every
  event with the unsent ones marked, and the state. It can be resized, and it can send now.
- **The page's code is in the repository.** It had been built from the session's scratch space; it now lives in
  `site/assets/review/` and `scripts/review/home-diff/`, built with `scripts/review/flat-page.py`.

What was not done: draining the lane from a browser. The vaults on sgit.ai drain in a script and show what was
drained in a dashboard vault app, and the vault bridge cannot list a lane set up as this one is. The dashboard
for this vault is the next step, built the same way. Tested in a browser with the lane stubbed, at desktop
and phone widths; no live send was made for this release.
