## Behaviour-policy vaults: a section, read live, with the vault app

**A new section under Live demos: [Behaviour-policy vaults](abp-vaults.html).** One page per
deployment shape, starting with [Claude Code on the web](abp-vault-claude-code-web.html).
Each page reads the encrypted vault directly in the browser — the ref id derived from the
published read key with HMAC-SHA256, ciphertext fetched over CORS from the vault host,
decrypted with Web Crypto, ref → commit → tree → blob — so a push to the vault is live on
the next page load with no rebuild of this site. The reader is sgit.ai's house reader,
copied into the page as its brief asks. If the vault cannot be reached the page falls back
to the copy served from `site/vaults/` and says so in every status chip.

**Four altitudes of the same bytes.** The card (four counts and no score, the shape of
the home-page Index card with the one number that is not allowed removed); the tables (the
grant irreversible-first, the delta in its three lists, the licence's conditions next to
what enforces each); the vault's own app, booted in a sandboxed frame with an opaque
origin and served its reads over postMessage; and the file list from the live tree.

**The vault app, for the person who was handed it.** `index.html` inside the vault now
opens on *Start here*: what this is, badges with the counts, three next steps, an inline
map of where the four objects go and how they reach the agent, and the whole policy on
one screen as *here is what we want you to do* beside *here is what we do not* — each
"do not" with what actually enforces it. A *Give it to your agent* view offers the same
files three ways: copy-and-paste blocks (every file, and all seven in one prompt), a zip
built by the same script that renders the documents, and a PDF rendered from the app in
print mode. The *Mandate — correct it* view recomputes the delta as rows move and exports
the corrected `mandate.json`. The app declares read only and no external resource.

**The read key is published, in the form sgit declares for a deliberately published key.**
It is printed on the vault's page where a human can copy it, with the clone command and
the vault-browser link. The write side appears nowhere on this site; the test that fails
the build on a write credential is unchanged.

**Builds are idempotent.** The generator keeps the delta's timestamp when nothing that
feeds it has moved, so a rebuild that changes nothing writes nothing, and the zip in
`dist/` is byte-identical run to run and checked by CI like every other derived file.
`scripts/site/render-abp-vault-pdf.mjs` cuts the PDF deliberately, like a Lab edition.

Vault `ruj286tr` is at its third commit: the template with the grant check, the app, and
the start-here view with the zip and the PDF.
