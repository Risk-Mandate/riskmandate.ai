# v1.38.6 — The review vault gets a dashboard

9 October 2026. The lead asked to open the review vault and see what readers did, as statistics and
pictures, in the layout of the newer vaults on sgit.ai. The vault now opens on a dashboard, rebuilt each
time the lane is drained.

- **Drained the way the games' telemetry is.** A browser cannot list this lane: the vault bridge derives the
  lane's enum key from the read key, and this lane's comes from the write key. So the drain stays a script,
  `scripts/review/read-feedback.mjs`, and it now ends by rebuilding the dashboard
  (`scripts/review/build-dashboard.mjs`) with what it filed. Commit and push the vault after it, as before.
- **The dashboard is a vault app**: `index.html` and `app.json` in the vault, with the data inlined, no grants,
  and nothing written back. It uses the family's layout (a sidebar of numbered groups, a title bar with
  Previous and Next) and its four themes, with the tokens copied from the Threat-sized security vault.
- **What it shows:**
  - counts, messages over time, and events by type;
  - each question's choices as a stacked bar, with who chose what;
  - comments by section, with their screenshots;
  - one row per reader's browser, with its signature check;
  - a replay of each visit: how far down the page the reader was, minute by minute, what they did, and how
    long they stayed on each section;
  - every event, filterable;
  - the drain log.
- **A fix on the review page.** The slider recorded its value under the same name as the event's time, so a
  slider event had no time. It now records `value`, and no field can overwrite an event's time or type.
  Slider events sent before this release are left out of the replay.

What was not done: the dashboard was pushed to the vault (version v0.1.0, over the four messages drained so
far) and tested from a local copy with two simulated readers; it was not opened inside the vault host from
this session, whose browser does not trust the session's network proxy.
